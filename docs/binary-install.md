# Prebuilt HamClock and installer recovery

HamClock installation downloads a prebuilt **Debian 13 amd64, X11, 800×480**
static executable. No compiler, development headers, upstream source download or
on-device build is involved. The runtime still needs the installed X desktop and
normal system network configuration; this is not a generic binary for every OS.

## Fixed release

- Release: [hamclock-bin-1525bad751d441ba9b1ff252946351e2fc797759](https://github.com/AF4H/hamclock-installer/releases/tag/hamclock-bin-1525bad751d441ba9b1ff252946351e2fc797759)
- Archive: `hamclock-4.27-debian13-amd64-static.tar.gz`
- Pinned SHA256: `149c5cab1c4620afda7e3ad2e7e94a8d656b97bc613c96f01450e6f9f316bc06`
- Source SHA256: `b751226742033ad88fa900980af079ae99e01eb1c37cbbf6a6c3c91af7655deb`
- Patch: `monotonic-v1`, preserving the earlier elapsed-clock fix.

The executable is statically linked: inspection finds no ELF interpreter or dynamic
NEEDED entries. It bundles libc, C++ and X11 libraries, so updating these bundled
libraries requires rebuilding and re-pinning the release. The target is specifically
Debian 13 amd64; name-service/locale behavior still depends on the target's system
configuration and has not been established for other distributions.

The release includes matching source, the patch/build script, archive checksums,
license and build information. `scripts/build-hamclock.sh` runs unprivileged in a
Debian 13 CI container. To build from the attached source instead of its upstream
URL, set `HAMCLOCK_SOURCE_ARCHIVE=/path/to/hamclock-source-4.27.zip`. Source checksum
verification applies to both paths. A changed builder triggers a new release whose
tag includes the build commit. Builds may differ in timestamps; the installer pins
one exact published archive, rather than assuming byte-for-byte reproducibility.

`scripts/install-hamclock.sh` verifies the archive before extraction and checks its
file list. A mismatch stops installation before replacing the existing executable.
It installs by temporary file and rename and retains `~/.hamclock`. The cache checks
both the pinned archive marker and the installed executable's checksum. Old
source-build markers do not authorize reuse of an old executable.

## Bare-metal failure found on 2026-10-22

The supplied installer syslog showed that HamClock compilation and installation
**succeeded**. The subsequent Wi-Fi step ran `apt-get update`, which failed because
an active `deb cdrom:` installer-media source could not be accessed inside the
target chroot. The reported error was:

```
E: The repository 'cdrom://[...] trixie Release' does not have a Release file.
```

The Wi-Fi stage now backs up and disables active installer-media sources before
updating APT. Both `.list` and deb822 `.sources` files are handled; network entries
are retained. Mixed CD-ROM/network URIs in one deb822 stanza require manual
separation rather than silently disabling a network repository. Duplicate firmware
sources generated by the earlier script are removed when the main network source
already enables `non-free-firmware`; custom files are preserved. The preseed also
sets Debian's `apt-setup/disable-cdrom-entries` option for the finished installation.

The shared stage order is base, Wi-Fi/APT repair, binary installation, always-on
desktop and mDNS. Each stage is named in `/var/log/hamclock-installer.log`, and its
failure status is preserved. The installer syslog receives the last 80 log lines.
Inside Debian Installer, the full target log is
`/target/var/log/hamclock-installer.log`.

## Recover without repartitioning

Generate `build/repair-hamclock.sh` with `python3 scripts/build.py`, or use the
provided generated recovery script. After finishing Debian installation and booting
the installed system, copy it onto that machine and run:

```sh
sudo sh repair-hamclock.sh
sudo reboot
```

It executes the same embedded stages as the installer, including the APT fix. It
keeps the stored hostname, saved network connections and HamClock station settings.
It does not select, format or repartition disks. If setup fails, inspect
`/var/log/hamclock-installer.log` before retrying. When the target has been mounted
from installation media, the same reviewed script can run with `in-target` after
copying it into `/target/tmp`; that recovery path has not been tested directly.

## Validation

Both static-binary build jobs and their ELF/version checks passed in GitHub Actions.
The pinned release was downloaded independently and its checksum verified. In the
disposable Debian guest, an active installer-media source reproduced APT exit 100.
The generated recovery script disabled that entry, successfully updated APT, avoided
firmware-source duplication and reached `HamClock-stage=complete` through all five
stages. It downloaded and installed the exact published static binary. The binary
ran with the existing station settings, displayed the full dashboard and reported
4.27, backend `hamclock.com:80` and successful NTP responses through its status API.
After reboot, the static binary started automatically with zero restarts, the
status API responded, and mDNS hostname resolution remained working. A deliberately
bad archive checksum failed while leaving the installed executable unchanged. A correct repeat install passed with downloads blocked by a test shim.

Eight local tests cover the generated payloads, failure-status/log preservation,
CD-ROM source cleanup, source preservation, firmware deduplication, and prior clock,
session and USB regressions. ShellCheck passes. This is a reproduced target/guest
recovery test; a fresh full installation of the expanded ISO and physical static
binary operation remain unverified.
